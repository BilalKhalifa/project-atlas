# Design Language

Version: 1.0

---

## Atlas Design Laws

Privacy is a right. Not a feature.

Secure by default. Simple by design.

Search first.

Clarity over cleverness.

Motion communicates.

Animation is a reward, not a requirement.

Trust is earned through transparency.

Whitespace is a feature.

Every click should have a purpose.

Beautiful software is invisible software.

---

# Purpose

Atlas should feel calm, trustworthy, and effortlessly fast.

The interface should reduce cognitive load while giving users confidence that their digital life is safe.

Every visual decision should reinforce trust.

---

# Design Philosophy

Atlas follows five core principles.

## 1. Calm

The interface should never overwhelm users.

Avoid unnecessary visual noise.

Whitespace is a feature.

Information should breathe.

---

## 2. Intentional

Every element exists for a reason.

If a component doesn't improve understanding or interaction, remove it.

---

## 3. Fast

Users should feel that Atlas responds instantly.

Interactions should feel lightweight.

Avoid heavy animations or unnecessary transitions.

---

## 4. Familiar

Users should feel comfortable immediately.

Atlas should innovate through interaction, not by reinventing common UI patterns.

---

## 5. Crafted

Details matter.

Spacing.

Motion.

Typography.

Icons.

Everything should feel polished.

---

# Visual Principles

## Minimal before decorative

Decorations should never compete with content.

Content is always the hero.

---

## Function before aesthetics

Beauty should improve usability.

Never sacrifice clarity for visual effects.

---

## Progressive disclosure

Only show what users need.

Advanced options appear only when necessary.

---

## Consistency

The same interaction should always produce the same result.

Predictability builds trust.

---

# Layout Philosophy

Use generous spacing.

Avoid crowded interfaces.

Prefer larger click targets over compact density.

Content should align to a consistent grid.

Navigation should remain stable across the application.

---

# Surface System

Atlas uses layered surfaces instead of heavy containers.

Primary Surface

Main content.

Secondary Surface

Cards and grouped information.

Overlay Surface

Dialogs.

Command palette.

Dropdowns.

Context menus.

Floating panels.

---

# Glass Usage

Glass is used sparingly.

Allowed

✓ Command Palette

✓ Context Menus

✓ Dialogs

✓ Floating Navigation

✓ Quick Actions

Avoid

✗ Cards

✗ Tables

✗ Forms

✗ Dashboard widgets

Glass communicates hierarchy.

It is never decoration.

---

# Border Radius

Corners should feel modern but restrained.

Rounded enough to feel approachable.

Not exaggerated.

Consistency is more important than trendiness.

---

# Shadows

Use subtle elevation.

Avoid dark heavy shadows.

Prefer soft layered shadows that communicate depth.

Elevation should be meaningful.

---

# Typography Philosophy

Typography carries the interface.

Use weight and spacing before color.

Headings should feel confident.

Body text should prioritize readability.

Avoid long paragraphs inside the application.

---

# Color Philosophy

Color communicates meaning.

Not decoration.

Neutral colors should dominate.

Accent colors guide attention.

Success, warning, and error colors should remain accessible.

Avoid rainbow interfaces.

---

# Motion Language

Motion should answer three questions.

Where did something come from?

Where is it going?

Why did it move?

Animations should communicate.

Never distract.

---

# Motion Timing

Fast interactions

100–150ms

Standard transitions

180–250ms

Large layout changes

250–350ms

Never animate for longer than necessary.

---

# Icons

Icons support text.

They do not replace text.

Prefer outline icons.

Consistent stroke width.

Simple geometry.

Recognizable at small sizes.

---

# Illustrations

Use illustrations sparingly.

They should communicate warmth without becoming playful.

Avoid cartoon styles.

Prefer clean geometric illustrations.

---

# Empty States

Every empty state should help users move forward.

Never leave blank screens.

Explain.

Guide.

Suggest the next action.

---

# Loading States

Avoid unnecessary spinners.

Prefer skeleton loading.

Show progress when possible.

Fast perceived performance matters.

---

# Feedback

Every important action should receive feedback.

Copy

Saved

Deleted

Imported

Synced

The feedback should be subtle and disappear automatically.

---

# Accessibility

Accessibility is a requirement.

Never rely solely on color.

Keyboard navigation must work everywhere.

Focus states should always be visible.

Support screen readers.

Maintain sufficient color contrast.

---

# Search First

Search is a primary navigation method.

Users should be able to instantly find:

- Credentials
- Notes
- Cards
- Settings
- Actions
- Security Reports

Ctrl/Cmd + K opens Atlas Search.

---

# Overall Feeling

When someone opens Atlas, they should think:

"This feels calm."

"This feels trustworthy."

"This feels fast."

"I know exactly what to do."

Atlas should disappear into the background and let users focus on what matters.

---

# Motion Philosophy

Animation exists to communicate.

It should explain, confirm, and reward—not entertain.

Atlas avoids decorative motion that competes with the user's task.

Instead, animation highlights meaningful moments:

- A password is copied.
- The vault unlocks.
- A sync completes.
- A passkey is created.
- Password health improves.

Animation should never become visual noise.

> Animation is a reward, not a requirement.
